# llm-places-finder

> For the reasoning behind the design, see [`docs/DECISIONS.md`](docs/DECISIONS.md).

## What this is

This project lets a local LLM (running via Ollama, used through Open WebUI) answer "sushi near me"-style questions with real places. The model only decides *when* to search and *what query* to pass; a standalone FastAPI backend does the actual Google Maps lookup and returns an embedded map that renders inline in the chat.

## Prerequisites

- Python 3.11+
- [Ollama](https://ollama.com) installed, with a model pulled (used here: `llama3.1:8b` — any function-calling-capable model works, e.g. `mistral`, `qwen2.5`).
- [Open WebUI](https://openwebui.com) installed and running (default `http://localhost:3000`), connected to Ollama.
- A Google Cloud project with **billing enabled** and these APIs enabled: **Places API, Geocoding API, Directions API, Maps Embed API**. Only needed when `MAPS_PROVIDER=google`; the default `MAPS_PROVIDER=osm` needs no key or billing at all.
- An API key for that project (Google mode only), **restricted** to those APIs (plus an IP restriction to your server). Set a **budget alert / daily quota cap** in Google Cloud Console — manual step, not enforced by code.

## Setup

1. Clone this repo and enter it:
   ```bash
   cd llm-places-finder
   ```
2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
3. Copy the example env and fill in your key:
   ```bash
   cp .env.example .env
   # edit .env: optionally set BACKEND_API_URL, rate limits
   ```
   This works out of the box with no API key — it defaults to free
   OpenStreetMap data. To use Google Maps instead, set
   `MAPS_PROVIDER=google` and `GOOGLE_MAPS_API_KEY` in `.env`.
   Switching providers requires no code changes, just the two env vars above.
4. Run the backend:
   ```bash
   uvicorn api.main:app --reload
   ```
   **Run with Docker** (alternative — same service, containerized):
   ```bash
   docker compose up --build
   ```
   This builds the `api` image and starts it on port 8000 using the
   variables in your `.env` file. Ollama and Open WebUI still run
   separately (they're not part of this container).
5. Verify it (no Open WebUI needed) — same check for both paths:
   ```bash
   curl -X POST localhost:8000/places/search \
     -H 'Content-Type: application/json' \
     -d '{"query":"ramen","near":"Malang"}'
   curl localhost:8000/health
   ```
   Auto-generated API docs: `http://localhost:8000/docs`.
6. Separately, install the Tool in Open WebUI: copy `tools/find_places.py` into Open WebUI's Tools directory (or paste it via Admin UI → Tools), set `BACKEND_API_URL` if your backend isn't on `http://localhost:8000`, and enable it for your model.

## Usage

Type any of these in Open WebUI chat (with the tool enabled):

- `Find sushi near me` → model calls `find_places(query="sushi")` → inline map of the top result.
- `Nearest pharmacy in Malang` → `find_places(query="pharmacy", near="Malang")`.
- Follow-up: `How do I get there from Malang station?` → `get_directions(origin="Malang station", destination_place_id="<from results>")` → inline route map with distance/duration.

End to end: LLM decides → Tool POSTs to `localhost:8000/places/search` → backend calls Google Maps → backend returns `{embed_html, fallback_link, results}` → Tool renders the iframe inline in chat.

### API documentation

Interactive docs are generated by FastAPI — no extra setup:

- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`

Opening `http://localhost:8000/` in a browser redirects to the Swagger UI.

## Known limitations

- No automatic quota rotation — one key, backend rate limit only.
- Single-language support (whatever Google returns; no translation layer).
- In-memory TTL cache and rate limiter are per-process; lost on restart, not shared across instances.
- No auth on the backend — localhost-only by design; add an API-key header before exposing it.
- No multi-turn location memory (each call is stateless; "near me" needs an explicit `near`).
- Keyless iframe embeds used to keep the secret server-side; styling/behavior limited to what the universal embed supports.
